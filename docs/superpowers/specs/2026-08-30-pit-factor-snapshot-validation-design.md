# PIT 因子快照驱动的历史验证

## 目标

历史验证默认使用 `FACTOR` 评分模式，不依赖既有模型运行或模型预测。它按调仓日自动复用或生成 PIT 因子快照，以研究模板实时合成横截面分数后执行回测。

## 数据模型

新增 `factor_snapshot` 与 `factor_snapshot_item`：

- `factor_snapshot` 由 `(as_of_date, factor_version, pit_version, universe_version)` 唯一确定，记录状态、覆盖率、输入审计信息、创建和完成时间。
- `factor_snapshot_item` 由快照和证券代码唯一确定，记录各因子维度分、维度可用状态和审计字段。
- 快照不保存模板最终综合分；模板变化不会使 PIT 快照失效。
- 自动补快照记录 `completed`、`failed` 或 `partial`。失败原因被安全清理后持久化。

## 验证流程

1. 根据回测区间和月度频率生成调仓日 T。
2. 以 `(T, factor_version, pit_version, universe_version)` 查找快照。
3. 命中时复用；未命中时，仅以 T 收盘时可见的行情、估值、财务披露和历史股票池计算快照并持久化。
4. 对每个快照项目，按所选模板对可用因子权重重新归一化，得到综合分和模板覆盖率。
5. 模板覆盖率低于 70% 的证券排除；其余证券按综合分排序，选择 Top N 并等权建仓。
6. 信号在 T 收盘后生成，第一版统一在 T+1 下一交易日开盘成交，并计入成本。
7. 任一所需快照无法生成或可交易样本不足时，验证记录为 `partial` 或 `insufficient_data`，不得作为正常有效回测展示。

## 策略类型

- `FACTOR`：默认模式，直接消费快照与模板权重。
- `MODEL`：保留现有模型运行路径，作为后续独立策略类型；本次改造不得改变其行为。

## 时间边界

- 财务数据只可在披露日的下一交易日及之后进入 T 的快照。
- 行情、估值和股票池均不得晚于 T。
- 成交日严格晚于信号日；不得使用 T 之后公开的数据形成 T 信号。

## 验收与测试

测试覆盖：快照命中不重算、缺失自动补算、同版本唯一性、历史股票池、模板 70% 覆盖率、缺失权重归一化、PIT 财报边界、T+1 成交边界、部分/不足状态，以及原 MODEL 路径不受影响。
